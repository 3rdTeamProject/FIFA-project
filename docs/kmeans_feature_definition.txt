============================================================
FC Online 플레이 스타일 군집화
1차 K-Means Feature 정의서
============================================================

작성 목적
------------------------------------------------------------

FC Online 경기 데이터에서 플레이 스타일을 발견하기 위해
1차 K-Means 군집화에 어떤 데이터를 사용하고,
어떤 데이터를 제외했는지를 기록한다.

중요:
원본 match_team_data.csv의 컬럼을 실제로 삭제하는 것이 아니다.
원본 데이터는 모두 보존하고,
K-Means 학습에 사용할 Feature만 별도로 선택한다.

2. 원본 데이터에서 플레이 스타일 분석에 제외한 정보
============================================================

다음 정보들은 match_team_data.csv에는 그대로 보존한다.

하지만 플레이 스타일을 발견하기 위한
1차 K-Means Feature에는 사용하지 않는다.


------------------------------------------------------------
A. 식별 정보
------------------------------------------------------------

matchId
- 경기 고유 ID
- 플레이 스타일과 직접적인 관계 없음


matchDate
- 경기 날짜
- 플레이 스타일 자체를 나타내는 정보가 아님


matchType
- 경기 종류
- 현재 동일한 경기 종류를 분석하므로 군집화 Feature에서 제외


ouid
- 유저 고유 ID
- 플레이 스타일을 나타내는 숫자가 아님


nickname
- 유저 닉네임
- 플레이 스타일과 직접적인 관계 없음


------------------------------------------------------------
B. 티어 / 시즌 / 환경 정보
------------------------------------------------------------

division
- 유저의 티어 정보
- 실력 수준과 관련될 수 있지만 플레이 방식 자체는 아님
- K-Means에서는 제외
- 추후 Cluster별 티어 분포 분석에는 사용 가능


seasonId
- 시즌 정보
- 플레이 방식 자체를 표현하는 Feature가 아니므로 제외


controller
- 키보드 / 게임패드 등의 컨트롤러 정보
- 1차 플레이 스타일 군집화에서는 제외


------------------------------------------------------------
C. 경기 결과 관련 정보
------------------------------------------------------------

matchResult
- 승 / 패 / 무승부
- 플레이 방식이 아니라 경기 결과이므로 제외


averageRating
- 경기 평점
- 플레이 스타일보다 경기 수행 결과/성과에 가까우므로 제외


goalTotal
goalTotalDisplay

- 득점 결과
- 플레이 스타일보다 공격의 최종 결과에 가까움


ownGoal
- 자책골
- 플레이 스타일을 나타내는 핵심 Feature가 아님


goalHeading
goalFreekick
goalInPenalty
goalOutPenalty
goalPenaltyKick

- 각 방식으로 실제 득점한 결과
- 1차 모델에서는 '어떻게 시도했는가'를 더 중요하게 보기 때문에 제외


------------------------------------------------------------
D. 경기 진행 / 이벤트 관련 정보
------------------------------------------------------------

matchEndType
- 경기 종료 형태
- 플레이 스타일 자체를 표현하지 않으므로 제외


systemPause
- 일시정지 관련 정보
- 플레이 스타일과 직접적인 관계가 적음


foul
- 파울 횟수
- 1차 플레이 스타일 분석에서는 제외


injury
- 부상 정보
- 플레이 스타일 군집화에서 제외


redCards
yellowCards

- 카드 정보
- 우연성 및 경기 상황의 영향을 받을 가능성이 있어
  1차 K-Means에서는 제외


cornerKick
- 코너킥 횟수
- 공격 상황과 관련될 수 있으나
  1차 모델에서는 제외


offsideCount
- 오프사이드 횟수
- 침투 성향과 관련될 가능성은 있으나
  한 경기의 우연성도 있기 때문에
  1차 모델에서는 제외

============================================================
5. 만들어 두었지만 첫 K-Means에서 제외한 Feature
============================================================

tackle_attempted
한글명:
태클 시도 여부

값:
태클 시도 있음 = 1
태클 시도 없음 = 0


현재 데이터:

전체 경기-유저 행 = 4089
태클 시도 없음 = 12

즉 약 99.7%의 데이터에서 tackle_attempted = 1이다.

대부분 동일한 값을 가지므로
첫 K-Means에서 군집을 구분하는 정보량이 매우 적을 것으로 판단하여
첫 실험에서는 제외한다.

단, match_ml_features.csv에는 해당 컬럼을 그대로 보존한다.


============================================================
6. 시도 여부 Feature를 만든 이유
============================================================

기존 safe_divide 함수에서는 분모가 0이면
비율을 0으로 처리한다.

예:

경기 A
shootTotal = 5
effectiveShootTotal = 0

effective_shoot_rate = 0
shoot_attempted = 1


경기 B
shootTotal = 0
effectiveShootTotal = 0

effective_shoot_rate = 0
shoot_attempted = 0


성공률만 사용하면 두 경기 모두 0이 되어
서로 구별할 수 없다.

따라서 shoot_attempted 등의 Feature를 함께 사용하여

"시도했지만 성공하지 못함"

과

"아예 시도하지 않음"

을 구분한다.

============================================================
8. 1차 K-Means의 목적
============================================================

이번 K-Means의 목적은 미리 정해진 플레이 스타일을
강제로 분류하는 것이 아니다.

각 경기의 플레이 Feature를 이용하여
데이터에서 자연스럽게 나타나는 경기 플레이 패턴을 발견하는 것이다.

따라서 처음부터

점유형
역습형
수비형
슈팅형

등의 이름을 정하지 않는다.

K-Means 실행 후 각 Cluster의 Feature 평균을 비교하여
실제로 어떤 특징이 강한 군집인지 확인한 뒤
해석 가능한 플레이 스타일 이름을 부여한다.

9. 이후 분석 순서
============================================================

match_ml_features.csv
        ↓

첫 K-Means Feature 20개 선택
        ↓

StandardScaler
        ↓

K-Means
K = 2 ~ 8 비교
        ↓

Silhouette Score 비교
        ↓

유력한 K 후보 선택
        ↓

Cluster별 Feature 평균 비교
        ↓

각 Cluster의 실제 플레이 패턴 해석
        ↓

플레이 스타일 이름 부여
        ↓

향후 유저의 여러 경기 Cluster 분포를 이용하여
유저의 평소 플레이 스타일 분석
